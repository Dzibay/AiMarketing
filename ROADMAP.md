# AiMarketing — план развития

Целевой пользователь — **фрилансер-директолог с множеством клиентов**. Задача продукта:
снять рутину, собрать все кабинеты клиентов в одном интерфейсе и дать ИИ-помощника,
который предлагает действия, а не применяет их сам.

## Принятые решения

| Вопрос | Решение |
| --- | --- |
| Пользователь | Фрилансер. Без команд, ролей, клиентского доступа и white-label |
| Доступ к Директу | Отдельный логин Яндекса на каждого клиента (много OAuth-подключений) |
| Каналы кроме Яндекса | VK Реклама, затем маркетплейсы (Ozon, Wildberries) |
| ИИ | Свой ключ пользователя в настройках: OpenAI-совместимый провайдер (свой base URL) и YandexGPT |
| Хостинг | Россия → OpenAI-подобные провайдеры только через base URL (прокси, OpenRouter, DeepSeek) |
| Автономия ИИ | По умолчанию каждое изменение — после подтверждения. В настройках пространства можно разрешить категории действий без согласования (бюджеты и ставки — не больше чем на N% за раз, по умолчанию 30%) или включить полный доступ |
| Структура | Аккаунты Метрики и Директа подключаются на уровне всего аккаунта. Рабочее пространство — один счётчик Метрики; в него добавляются логины Директа и их кампании, у каждой кампании хранится логин-источник. Клиент — папка над пространствами |
| Песочница | Песочница Директа подключается отдельным логином: на ней проверяются запись и ИИ-действия без денег |
| Главная рутина | Чистка поисковых запросов, контроль всех кабинетов, запуск кампаний |
| Стадия | Тестирует только автор, схему БД можно перестраивать |

Допущения (поправить, если неверно): VK раньше маркетплейсов, Ozon и WB вместе, биллинг пока не нужен.

## Принципы

- ИИ предлагает — маркетолог подтверждает одним кликом (или заранее разрешает категорию
  действий). Журнал действий и откат.
- Без ИИ-ключа сервис полезен сам по себе: сводка, алерты, правила.
- Одна лента рекомендаций: правила, ИИ и аномалии кладут туда карточки
  «что случилось → что сделать → ожидаемый эффект».

## Фаза 0. Фундамент

- [x] Alembic: базовая миграция повторяет текущую схему, дальше только миграции
- [x] Клиенты: таблица `clients`, привязка подключений, кабинетов Директа и счётчиков Метрики;
      KPI клиента (CPA или ДРР, целевое значение, месячный бюджет)
- [ ] Общая таблица рекламных кабинетов с полем площадки (Директ / VK / Ozon / WB)
- [ ] Ссылка-приглашение: клиент сам входит своим логином Яндекса, токен попадает к фрилансеру
- [x] Контроль здоровья токенов: истекает, отозван, ошибка синка (в «где горит»)
- [x] Очередь задач в Postgres (`FOR UPDATE SKIP LOCKED`): задачи на кабинет, ретраи с backoff,
      прогресс в интерфейсе; никаких долгих синков внутри HTTP-запроса
- [ ] Клиент API Директа: учёт `Units`, `retryIn` для отчётов, инкрементальный синк через Changes
- [ ] Дневные факты с историей: кампания × группа × ключ/объявление, поисковые запросы по дням
- [x] Внутридневной расход «сегодня» (раз в час и по кнопке) и балансы общего счёта (Live 4)
- [x] Интеграционные тесты с Postgres (`TEST_DB_*`, в CI — сервис postgres)
- [ ] Разнести `api/web.py` по доменным роутерам; Sentry; сборка фронта в CI

## Фаза 1. Контроль всех кабинетов (без ИИ)

- [x] Сводка по клиентам: расход сегодня / вчера / 7 дней, CPA или ДРР против цели,
      темп расхода месячного бюджета, дней на балансе
- [x] Проблемы: модерация, остановленные кампании, ошибки синка, токены. Сортировка «где горит»
- [x] Аномалии статистикой: скачки расхода и CPA, расход без конверсий
- [x] Утренний дайджест в Telegram по всем клиентам
- [x] Общие списки минус-фраз и словари стоп-слов (5 шаблонов), применение к кампаниям
      нескольких клиентов: предпросмотр → подтверждение → задача очереди. Слияние на уровне
      кампании: список помнит, какие фразы добавил сам, ручные и чужие фразы не трогает
- [ ] Проверить списки на живом Директе: очистка минус-фраз через `null`, `campaigns.get`
      по Id архивных кампаний, единые (UNIFIED) кампании через v5
- [ ] Массовый «дневной бюджет» в «Кампаниях» шлёт до 100 кампаний одним `campaigns.update`,
      а Директ принимает не больше 10 — разбить на пачки
- [ ] Таблица с сортировкой, фильтрами, выбором колонок и сохранёнными видами
      (сейчас: сортировка и фильтр «только с проблемами», запоминаются в браузере)
- [ ] Проверить на живом Директе баланс Live 4 и поле Revenue (пока только моки)

## Фаза 1.5. Рабочие пространства и ИИ-чат

- [x] Аккаунт (`/cabinet/accounts`): несколько логинов Метрики и Директа, счётчики и кампании
      подтягиваются сами; песочница Директа — отдельной кнопкой и с пометкой «песочница»
- [x] Рабочее пространство на каждый счётчик Метрики, выбор счётчика в шапке; клиент — папка
      (группировка в переключателе и на странице клиентов)
- [x] Настройки пространства: название, клиент, KPI, логины Директа, состав кампаний
      (кампания живёт в одном пространстве, перенос — с подтверждением), доступ ИИ.
      Подсказка, если у логина Директа нет доступа к счётчику
- [x] Сводка пространства: расход, конверсии, CPA / ДРР против цели, проблемы
- [x] Аналитика пространства: Директ + Метрика по кампаниям пространства, тренд, конверсии
      по цели Метрики
- [x] Кампании: список с фильтрами и массовыми действиями (пауза, запуск, архив, удаление,
      дневной бюджет, копия), карточка кампании со структурой — группы, ключи (с CSV),
      объявления, запросы
- [x] Мастер создания кампании (TEXT и ЕПК): выбор логина Директа, стратегия, бюджет,
      расписание, счётчики и приоритетные цели, первая группа с ключами и объявлением;
      создаётся черновиком, на модерацию — отдельной кнопкой
- [x] Настройки кампании: стратегия, бюджет, даты, расписание показов, минус-фразы,
      исключённые площадки, счётчики, цели, UTM
- [x] Копия кампании со структурой — в тот же или другой логин, в это или другое пространство
- [x] Правила на уровне пространства; журнал действий (кто: пользователь, ИИ, правило)
- [x] Настройки → ИИ: OpenAI-совместимый провайдер (свой base URL) или YandexGPT (folder id),
      ключ шифруется, «Проверить подключение», запрет base URL во внутреннюю сеть
- [x] ИИ-чат пространства: анализ кампаний с рекомендациями, инструменты чтения и записи
      (статистика, запросы, структура, бюджеты, ставки, минус-фразы, ключи, объявления,
      создание и копирование кампаний). Каждое изменение — карточка «Выполнить / Отклонить»,
      «Выполнить все»; разрешённые категории и полный доступ — без согласования
- [x] Окно подтверждения вместо `window.confirm`
- [ ] Проверить на песочнице и живом Директе: создание ЕПК, копирование между логинами
      (быстрые ссылки, уточнения), настройки стратегий, `moderate` (пока только моки API)
- [ ] Стриминг ответа ИИ и отмена долгого шага; лимит токенов на чат

## Фаза 2. ИИ: подключение и чистка запросов

- [x] Настройки → ИИ: провайдер, base URL, ключ (зашифрован), «Проверить» (см. фазу 1.5)
- [ ] Модель на задачу (быстрая / умная), учёт токенов, месячный лимит
- [ ] LLM-слой: строгий JSON с валидацией и повтором, батчи, кэш, оценка стоимости
      перед массовой задачей, версии промптов
- [x] Бриф пространства: что продаём, гео, что точно «не наше», заметки; черновик по сайту
      (ИИ читает страницу, сохраняет только пользователь)
- [x] Чистка запросов (`/w/:id/queries`): правила (уже отсекается в Директе → память →
      «не наше» из брифа) → ИИ с причиной, минус-фразой и уровнем → проверка, что минус
      не режет свои ключи → подтверждение пачкой; запрос без группы минусуется в кампании
- [x] Память решений по пространству: подтверждённое не переспрашивается и служит ИИ
      примерами; вкладка «Память» с «Забыть»
- [x] Откат из журнала: действия хранят обратные шаги, «Вернуть как было» с превью шагов
      и предупреждением, если объект меняли позже; откат тоже пишется в журнал
- [ ] Проверить чистку и откат на живом Директе (пока моки API и заглушка ИИ)
- [ ] Общая очередь разбора по всем клиентам; лента рекомендаций
