# AiMarketing — план вывода в продажу

Цель — превратить личный инструмент в сервис по подписке, понятный человеку без опыта: открыл сводку,
спросил ИИ, подтвердил изменения. Что уже умеет сервис — в [README](README.md).

## Принятые решения (2026-11-10)

| Вопрос | Решение |
| --- | --- |
| Для кого | Все: фрилансеры-директологи, владельцы бизнеса. Команд, ролей и доступа для клиентов пока нет |
| Масштаб на старте | До 100 пользователей |
| Главное в интерфейсе | ИИ-чат, сводка, список кампаний. Остальное вторично |
| Проект | Проект = счётчик Метрики. Слово «пространство» заменяем на «проект» |
| Клиенты | Необязательная папка над проектами: нет клиентов — слово нигде не видно |
| Песочница Директа | Убрать: не работает |
| ИИ | Общий ключ сервиса, YandexGPT. Настройка — только в админке. Свой ключ пользователя убираем |
| Модели | Три класса (рабочие названия: Быстрая, Стандартная, Думающая), цена каждого — в условных единицах, задаётся в админке. В чате модель выбирает пользователь |
| Вордстат и картинки | Общий ключ сервиса. Цена запроса Вордстата и одной генерации — в единицах, задаётся в админке |
| Что видит пользователь | Месячную шкалу лимита без денег и токенов и детализацию: модели, Вордстат, картинки. Цену перед операциями не спрашиваем |
| Тарифы | Пробный + три платных. Различаются лимитом, числом проектов и функциями. У пользователя тариф с датой окончания; админ меняет всё |
| Остаток лимита | Сгорает в конце периода |
| Лимит исчерпан | ИИ и Вордстат стоят до нового периода + предложение тарифа выше со скидкой за переход (скидка задаётся в админке) |
| Подписка закончилась | Всё закрыто, показываем уведомление и «Продлить». Данные храним бессрочно |
| Защита пробного периода | Подтверждение почты. Логин Яндекса, счётчик и кабинет Директа подключаются только к одному аккаунту |
| Оплата | ЮKassa, настройки в админке. Продавец — самозанятый; в документах без персональных данных |
| Скидки, промокоды | Скидок пока нет. Промокоды и реф-ссылки для разметки трафика — в админке |
| Админка | Только владелец. Видит всё, включая чаты. Журнал действий админа не нужен |
| Поддержка | Виджет в интерфейсе ↔ Telegram-группа с темами: сообщение пользователя создаёт тему, ответ в теме уходит пользователю |
| Уведомления админу | Telegram-бот: подключается и настраивается в админке |
| Стартовая страница | Сводка |
| ИИ-чат | Общий по всем проектам + чаты внутри проектов |
| Мобильная версия | Все разделы |
| Лендинг и SEO | Позже |

## Принципы (остаются)

- ИИ предлагает — пользователь подтверждает одним кликом. Журнал действий и откат.
- Без ИИ сервис тоже полезен: сводка, «где горит», правила, дайджест.
- Фоновых вызовов ИИ нет: модель работает только по кнопке или сообщению пользователя.

## Интерфейс: целевая структура

Одно меню, которое не меняется от выбора проекта. Переключатель «Все проекты / Клиент → Проект» работает как
фильтр. Раскладку (меню слева, чат в центре или разделы сверху) выбираем по макетам — промпты
в [docs/ui-prompts.md](docs/ui-prompts.md).

- **Разделы:** Сводка, ИИ-помощник, Кампании, Чистка запросов, Аналитика, Автопилот, История, Настройки проекта.
  Внизу: Подключения, Настройки, Тариф.
- **Всегда на экране:** переключатель проекта, шкала лимита, «Ждёт решения» (предложения ИИ по всем проектам),
  профиль, виджет поддержки.

| Сейчас | Станет |
| --- | --- |
| Обзор кабинета | Сводка при «Все проекты» |
| Пространство → Сводка | Сводка при выбранном проекте |
| Обзор → Аналитика, Площадки, Объявления (вкладки в шапке) | Аналитика: вкладки на странице |
| Кампании → Поисковые запросы | Чистка запросов — отдельный раздел |
| Инструменты → Минус-фразы | Чистка запросов → Списки минус-фраз |
| Инструменты → Общие правила, Автоматизация → правила | Автопилот → Правила (общие и проекта) |
| Автоматизация → Эксперименты | Автопилот → Эксперименты |
| Автоматизация → Быстрые действия | Убрать: дублирует другие разделы |
| Журнал изменений | История |
| Клиенты (страница) | Клиент выбирается в настройках проекта, группировка — в переключателе и на Сводке |
| Аккаунты | Подключения |
| Настройки → ИИ, Мост, Вордстат, Картинки | Админка |
| Настройки → Расход ИИ | Тариф |
| Настройки → Telegram, Пароль | Настройки → Профиль, Уведомления |
| Настройки пространства | Настройки проекта — пункт меню |
| Песочница Директа | Убрать |

## Фазы

Порядок выбран так, чтобы фазы 1–2 шли, пока выбирается раскладка: они от неё не зависят.

### Фаза 1. Общие ИИ, Вордстат и картинки, учёт в единицах

- [x] Вход в админку под своим аккаунтом с ролью администратора (назначается через `.env`) вместо общего
      пароля; оболочка админки в стиле кабинета
- [x] Админка → ИИ и сервисы: YandexGPT (каталог, ключ шифруется), три класса моделей — название, модель,
      цена в единицах за 1 млн токенов входа и выхода, себестоимость в ₽ (для маржи), вкл/выкл;
      какой класс у фоновых задач (разметка запросов, бриф, площадки); «Проверить подключение»
- [x] Вордстат: ключ и каталог сервиса в админке (сейчас в `.env`), цена запроса в единицах
- [x] Генерация картинок: ключ сервиса, цена генерации в единицах
- [x] Мост Cloudflare — только в админке
- [x] Учёт расхода: каждое списание — строка (пользователь, проект, вид: класс модели / Вордстат / картинка,
      единицы, токены, себестоимость в ₽). `ai_usage` расширяем; запросы Вордстата сейчас не пишутся — добавить
- [x] Проверка лимита в одном месте перед каждым платным вызовом; при нуле — понятная ошибка
- [x] Выбор модели в чате: Быстрая ●○○ / Стандартная ●●○ / Думающая ●●● (точки — относительный расход)
- [x] Убрать свой ключ пользователя: разделы ИИ, Мост, Вордстат, Картинки, Расход ИИ из настроек;
      таблицы `ai_settings`, `wordstat_settings`, `image_gen_settings` по пользователю — удалить миграцией
      (если ключ был ровно у одного пользователя, миграция переносит его в админку, иначе ключи вводятся заново)
- [x] Убрать песочницу Директа: подключение, пометки, ветки кода

### Фаза 2. Тарифы, лимиты и доступ

- [ ] Тарифы в админке: название, цена ₽, срок в днях, лимит единиц, число проектов, функции. Пробный — тоже
      тариф (дни + лимит). Кандидаты на функции по тарифу: автопилот, эксперименты, генерация картинок,
      Вордстат, общий чат, дайджест в Telegram
- [ ] Подписка пользователя: тариф, начало, окончание; лимит, проекты и функции админ может поменять поверх
      тарифа. Период лимита = оплаченный период, остаток сгорает
- [ ] Скидка за переход с тарифа на тариф: таблица «с какого → на какой, %» в админке
- [ ] Подписка закончилась: доступ закрыт, экран «Продлить», данные хранятся. Синки и правила для таких
      аккаунтов останавливаются, после оплаты — догрузка
- [ ] Лимит исчерпан: ИИ, Вордстат и картинки останавливаются до нового периода; окно с тарифом выше и скидкой;
      предупреждения на 80% и 100%
- [ ] Лимит проектов: проекты больше не создаются сами на каждый счётчик — пользователь отмечает счётчики
      в пределах тарифа, остальные видны с пометкой «на тарифе выше»
- [ ] Закрытые по тарифу разделы видны с замком и предложением перейти
- [ ] Подтверждение почты при регистрации; без него — только экран «Подтвердите почту». Вход через Яндекс ID
      считается подтверждённым
- [ ] Один логин Яндекса — один аккаунт (сейчас уникален только внутри аккаунта). Счётчик Метрики и кабинет
      Директа — тоже только в одном аккаунте; при попытке — «уже подключён в другом аккаунте, напишите
      в поддержку»
- [ ] Журнал событий пользователя: регистрация, подтверждение почты, вход, подключение Яндекса, проект, вопрос
      ИИ, выполненное предложение, лимит исчерпан, оплата, смена тарифа. Пишем с этой фазы, чтобы к админке
      накопилась статистика

### Фаза 3. Новый интерфейс (после выбора раскладки)

- [ ] Переименования: пространство → проект, аккаунты → подключения. Номер счётчика и логины — во второй план
- [ ] Одно меню и переключатель проекта как фильтр
- [ ] Сводка — стартовая страница: при «Все проекты» — нынешний обзор кабинета, при проекте — сводка проекта
- [ ] ИИ-помощник: общий чат по всем проектам (инструменты получают проект параметром, запись — только
      с подтверждением) и чаты проектов
- [ ] «Ждёт решения»: все неподтверждённые предложения ИИ по всем проектам одним списком, счётчик в шапке
- [ ] Кампании: при «Все проекты» — общий список с колонкой проекта
- [ ] Чистка запросов: отдельный раздел; при «Все проекты» — общая очередь разбора; вкладка «Списки минус-фраз»
- [ ] Аналитика: динамика, площадки, объявления
- [ ] Автопилот: правила (общие и проекта) и эксперименты
- [ ] История: журнал с откатом, фильтры по проекту и источнику
- [ ] Клиенты: страница уходит, клиент выбирается в настройках проекта
- [ ] Настройки: Профиль (имя, почта, пароль), Уведомления (Telegram, дайджест)
- [ ] Тариф: шкала периода, доли по моделям, Вордстату и картинкам, расход по дням и проектам, сравнение
      тарифов, история платежей
- [ ] Мастер первого входа вместо чек-листа: почта → Яндекс → выбор проектов в лимите тарифа → загрузка →
      первый вопрос ИИ
- [ ] Мобильная версия всех разделов: нижняя панель и «Ещё»
- [ ] Подсказки «?» у терминов: CPA, ДРР, РСЯ, минус-фраза, ЕПК

### Фаза 4. Оплата, промокоды, реф-ссылки

- [ ] Админка → ЮKassa: shopId, секретный ключ, тестовый режим, проверка подключения
- [ ] Оплата тарифа: платёж → страница ЮKassa → уведомление `payment.succeeded` (статус перепроверяется через
      API) → продление подписки. Повторное уведомление не продлевает дважды
- [ ] Чеки самозанятого: проверить, что ЮKassa сама регистрирует доход в «Мой налог»
- [ ] Напоминания об окончании тарифа за 3 дня и за 1 день — в интерфейсе и на почту
- [ ] Платежи на странице «Тариф» и в админке; возвраты — вручную в ЮKassa, статус подтягивается
- [ ] Промокоды: что дают (единицы, дни, тариф на N дней), срок действия, число активаций; ввод при регистрации
      и на странице «Тариф»
- [ ] Реф-ссылки: `?ref=код` запоминается при первом заходе и сохраняется при регистрации. В админке по каждой:
      переходы, регистрации, подтверждения, оплаты, выручка
- [ ] Оферта и политика под тарифы и возвраты, без персональных данных продавца

### Фаза 5. Админка: статистика и пользователи

- [ ] Дашборд с выбором периода: регистрации по реф-ссылкам; воронка регистрация → почта → Яндекс → проект →
      первый вопрос ИИ → оплата; MRR, выручка, средний чек, отток, пробный → платный; активные за
      день / неделю / месяц; расход единиц по моделям, Вордстату и картинкам; себестоимость против выручки
      (маржа); топ по расходу; истекающие тарифы; ошибки синков и ИИ; очередь задач
- [ ] Пользователи: таблица с поиском, фильтрами (тариф, статус, источник, активность, «истекает скоро»)
      и сортировкой
- [ ] Карточка пользователя: профиль, источник, тариф, срок, лимит, проекты и функции с правкой на месте;
      начислить единицы, продлить, заблокировать, сбросить пароль, подтвердить почту. Вкладки: расход
      (по дням и моделям), проекты (счётчики, кабинеты, кампании, расход в Директе), подключения Яндекса
      (доступы, ошибки синков), чаты ИИ (чтение), история событий, журнал изменений в Директе, платежи, поддержка
- [ ] Отдельные страницы: платежи, тарифы, промокоды и реф-ссылки
- [ ] Система: очередь задач, ошибки синков и ИИ

### Фаза 6. Поддержка и Telegram админа

- [ ] Админка → Telegram: токен бота (один бот на уведомления пользователям, админу и поддержку; нынешний токен
      из `.env` переезжает сюда), привязка своего чата, выбор уведомлений: регистрация, подтверждение почты,
      оплата, конец пробного периода, лимит исчерпан, всплеск ошибок, новое обращение
- [ ] Виджет поддержки в интерфейсе: переписка, скриншоты, бейдж непрочитанного
- [ ] Связка с Telegram-группой с темами: первое сообщение пользователя создаёт тему «ID · почта · тариф»,
      дальше переписка идёт в ней; ответ в теме уходит пользователю в виджет, а если он не в сети — ещё и на почту
- [ ] Обращения видны в карточке пользователя в админке

### Фаза 7. Перед запуском

- [ ] Резервные копии БД по расписанию и проверка восстановления
- [ ] Ограничение частоты регистрации, входа и сброса пароля
- [ ] Мониторинг ошибок
- [ ] Проверка на 100 пользователей: число воркеров, лимиты API Директа и Метрики, квота Вордстата

## Открытые вопросы

1. Раскладка интерфейса: меню слева, чат в центре или разделы сверху — после макетов.
2. Тарифы: названия, цены, лимиты, число проектов, какие функции закрыты на младших.
3. Переход на тариф выше посреди периода: остаток дней и лимита старого тарифа сгорает, переносится или
   засчитывается в цену?
4. Автопродление (рекуррентные платежи ЮKassa) или ручная оплата каждый период.
5. Показывать ли пользователю число единиц («1 240 из 5 000») или только проценты.
6. Окончательные названия классов моделей.
7. Квота Вордстата при общем ключе (100 запросов в час на каталог): кэш, несколько ключей, очередь.
8. Какие ещё эффекты нужны промокодам, кроме единиц, дней и тарифа.
9. Риски: ЮKassa при подключении проверяет сайт (оферту, контакты, данные продавца), и закон о защите прав
   потребителей требует, чтобы покупатель знал продавца — возможно, ИНН самозанятого всё же придётся указать.
   Лимит дохода самозанятого — 2,4 млн ₽ в год.
