# AiMarketing

SaaS-кабинет для автоматизации Яндекс Директа и Метрики.

Стек как у Aimarket: Vue 3 + FastAPI + Postgres + Nginx + Caddy.

## Что уже есть

- Регистрация и вход по почте, OAuth Яндекса (Метрика + Директ), песочница Директа
- Аккаунты: несколько логинов Метрики и Директа; счётчики и кампании подтягиваются сами,
  у каждой кампании хранится логин-источник
- Рабочие пространства: одно на счётчик Метрики (выбор в шапке) — сводка, аналитика, кампании,
  действия, ИИ-чат и настройки; логины Директа и кампании добавляются в настройках пространства
- Кампании пространства: мастер создания (TEXT, ЕПК) с выбором логина, настройки стратегии,
  бюджета и расписания, копия в другой логин или пространство, отправка на модерацию
- ИИ-ассистент со своим ключом (OpenAI-совместимый или YandexGPT): анализ и рекомендации,
  действия через карточки согласования, настраиваемый доступ и полный доступ; быстрая модель
  для массовых задач, учёт токенов и рублей, месячный лимит, оценка стоимости перед разметкой
- Клиенты-папки: карточка с KPI (CPA / ДРР) и бюджетом, группировка пространств;
  новые кабинеты при синке раскладываются по клиентам автоматически
- Сводка по всем клиентам: расход сегодня / вчера / 7 дней, KPI против цели, темп месячного
  бюджета, баланс и дни на нём; «где горит» — токены, синки, баланс, бюджет, KPI, модерация,
  остановленные кампании и аномалии (скачки расхода и CPA, расход без конверсий)
- Утренний дайджест в Telegram: вчерашние итоги по клиентам и «где горит», час — в кабинете
- Кампании: синк, пагинация, массово пауза/запуск/архив/удаление/бюджет
- Группы объявлений и TextAd: синк, создание, правка, пауза/архив/удаление
- Ключевые фразы: синк, добавление, ставка, пауза/запуск/удаление
- Минус-фразы кампании и группы объявлений
- Общие списки минус-фраз (стоп-слова) для кампаний разных клиентов: шаблоны, предпросмотр
  изменений по каждой кампании и запись в Директ только после подтверждения
- Поисковые запросы: синк, фильтры, массово в ключи / минуса группы или кампании
- Статистика периода по группам и ключам (вместе с синком запросов)
- Аналитика пространства: Директ + Метрика, сравнение с прошлым периодом, конверсии по цели
  Метрики, догрузка за 30 дней, тренд, топы ключей / групп / запросов; CSV ключей кампании
- Онбординг-чеклист и смена пароля в кабинете
- Правила: кампании, ключи и поисковые запросы; CPA/CPC/расход; пауза/ставка/минуса/notify; dry-run
- История sync_runs в кабинете; сброс пароля (SMTP или ссылка в лог)
- Telegram-алерты по правилам (бот + привязка через /start)
- Очередь задач в Postgres: все синки идут фоном с прогрессом и ретраями, расписание в БД
- Миграции схемы через Alembic; pytest (юнит + интеграционные с Postgres) / CI
- Админка (блок/разблок) и юрстраницы; OAuth без session token в URL

## Быстрый старт

```bat
copy .env.example .env
```

Заполните обязательные поля в `.env`, затем:

```bat
docker compose up -d --build
```

Сервисы: `postgres`, `backend` (API без встроенных циклов), `worker` (очередь задач, расписание, Telegram), `nginx`, `caddy`.
Локально без Docker API по умолчанию поднимает воркеры в том же процессе (`RUN_EMBEDDED_WORKERS=true`).

## Схема БД и очередь задач

Схема ведётся миграциями Alembic (`backend/migrations/versions`). `backend` и `worker` при старте
сами делают `alembic upgrade head` (параллельный запуск сериализуется advisory-lock). Базовая
миграция повторяет бывший `database/init.sql` и идемпотентна — БД, созданная до Alembic,
подхватывается без пересоздания.

```bat
cd backend
alembic upgrade head
alembic revision -m "что меняем"
```

Миграции пишутся на SQL через `op.execute`; `alembic.ini` — только ASCII (Alembic читает его в кодировке ОС).

Долгие операции (синк подключения, кампаний, структуры, запросов, целей, статистики, правила)
не выполняются в HTTP-запросе: API ставит задачу в таблицу `jobs` и отдаёт `{"job": …}`, фронт
опрашивает `GET /api/web/jobs/{id}`. Исполнители берут задачи через `FOR UPDATE SKIP LOCKED`,
одинаковая активная задача не дублируется, ошибки Яндекса ретраятся с backoff, зависшие
(без heartbeat) возвращаются в очередь. Периодические синки планируются через `job_schedules`.
Число параллельных задач на процесс — `WORKER_CONCURRENCY` (по умолчанию 3).

Расписание (`workers.SCHEDULES`): подключения, кампании, статистика за вчера, раз в час — расход
за сегодня и балансы (`stats_today`), раз в 10 минут — проверка утреннего дайджеста
(`send_digest`), правила, чистка старых задач. «Вчера» и «сегодня» считаются по Москве
(`app/clock.py`), как и в Директе.

Локально без Docker:

1. Поднимите Postgres и пропишите `DB_*` в `.env`
2. `cd backend && pip install -r requirements.txt && python run_api.py`
3. `cd frontend && npm install && npm run dev`

## Яндекс OAuth

1. Создайте приложение на [oauth.yandex.ru](https://oauth.yandex.ru)
2. Callback URL: `{PUBLIC_BASE_URL}/api/web/yandex/callback`
3. Права: `login:info`, `login:email`, `metrika:read`, `direct:api`
4. Для Директа отдельно подайте заявку на доступ к API в кабинете Яндекса
5. Пропишите `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `TOKEN_ENCRYPT_SECRET`, `PUBLIC_BASE_URL`

Новые LAL из ИИ-чата (необязательно). Приложение для авторизации держит не больше трёх групп прав,
а `login`, `metrika` и `direct` их уже занимают, поэтому Яндекс Аудитории — вторым приложением:

1. Ещё одно приложение на [oauth.yandex.ru](https://oauth.yandex.ru), тот же Callback URL
2. Права: `audience:read`, `audience:write`
3. Пропишите `YANDEX_AUDIENCE_CLIENT_ID`, `YANDEX_AUDIENCE_CLIENT_SECRET`
4. В «Аккаунтах» у логина Директа появится «Подключить Аудитории» — войти тем же логином

Без этих переменных кнопки нет, а ИИ предлагает только готовые условия кабинета.

## Поток «минимум действий»

1. Регистрация по почте → сводка по всем клиентам (`/cabinet`)
2. «Аккаунты» → «Подключить Метрику» / «Подключить Директ» → `oauth.yandex.ru`; каждый логин
   Яндекса подключается отдельно, их может быть сколько угодно
3. После согласия счётчики и кампании подтягиваются сами, на каждый счётчик появляется
   рабочее пространство, кампании раскладываются по счётчику из своих настроек
4. Выбор счётчика в шапке → пространство; в его настройках — логины Директа и состав кампаний

## Аккаунты и рабочие пространства

Уровень аккаунта (`/cabinet/...`): сводка по всем клиентам, `accounts` — подключения Метрики
и Директа, `clients` — клиенты-папки с KPI, `rules`, `negative-lists`, `settings` (пароль,
Telegram, ИИ).

Рабочее пространство — один счётчик Метрики (`/w/:id/...`): `summary`, `analytics`, `campaigns`
(и `campaigns/:cid` — карточка со структурой и настройками), `actions` (журнал), `chat`
(ИИ), `settings`. Пространства создаются при синке Метрики (`workspaces.ensure_workspaces`),
клиент задаётся в настройках пространства.

- Логин Директа подключается к любому числу пространств (`workspace_accounts`). При подключении
  можно забрать его кампании со счётчиком пространства, все свободные или ни одной.
- Кампания живёт в одном пространстве (`workspace_campaigns`), логин-источник хранится в самой
  кампании (`direct_campaigns.account_id`) — по нему идут все записи в Директ. Перенос кампании
  в другое пространство — с подтверждением.
- Директ принимает номер любого счётчика, но цели для стратегий видит, только если у логина
  кабинета есть доступ к счётчику в Метрике. Если логин кабинета сам подключён и видит
  счётчик — доступ подтверждён, иначе в настройках пространства и в мастере висит подсказка.
- Мастер создания кампании (`GET .../campaign-options`, `POST .../campaigns`): TEXT или ЕПК,
  логин Директа, стратегия и её параметры, бюджет, даты, расписание, счётчики, приоритетные
  цели, UTM, первая группа с регионами, ключами и объявлением. Кампания создаётся черновиком,
  на модерацию — `POST .../campaigns/{id}/moderate`.
- Копия (`POST .../campaigns/{id}/duplicate`) переносит настройки, группы, фразы и текстовые
  объявления — в тот же или другой логин и пространство. В чужом логине быстрые ссылки
  и уточнения пересоздаются, картинки, визитки и турбо-страницы — нет.
- Журнал (`GET .../actions?source=user|ai|rule`) пишет каждое изменение с источником.
  У большинства записей есть откат — см. «Чистка запросов, бриф и откат».

API пространств — `/api/web/workspaces`: список и `refresh`, карточка и `PATCH`, `summary`,
`analytics` и `analytics/sync`, `accounts` (+ `candidates`), `campaigns` (+ `candidates`, `set`,
`sync`, `actions`), `campaigns/{id}` и `campaigns/{id}/settings` (`GET` / `PATCH`), `duplicate`,
`moderate`, `actions`, `rules`.

## ИИ-ассистент

Ключ подключает сам пользователь: «Настройки → ИИ». Провайдеры — OpenAI-совместимый (свой
base URL: OpenAI, OpenRouter, DeepSeek, прокси) и YandexGPT (нужен folder id каталога).
Ключ хранится зашифрованным (`TOKEN_ENCRYPT_SECRET`), base URL во внутреннюю сеть запрещён.
API: `GET/PUT /api/web/ai/settings`, `POST /api/web/ai/settings/test`.

Чат живёт в пространстве и видит только его кампании. Модель вызывает инструменты (до 8 шагов
на сообщение):

- чтение — сводка, аналитика, кампании и их настройки, поисковые запросы (и их обновление),
  топы структуры, журнал, параметры для создания кампании;
- запись — пауза / запуск / архив / удаление, бюджет и настройки, минус-фразы, создание
  и копия кампании, модерация, группы, ключи и ставки, поисковые запросы в ключи или минуса,
  объявления.

Каждая запись сначала становится карточкой в чате (`ai_actions`): «Выполнить» / «Отклонить»
или «Выполнить все». В настройках пространства можно разрешить категории без согласования:
остановка и запуск, бюджеты, ставки, минус-фразы, ключи, объявления, кампании, удаление
и архив. Бюджет или ставка меняются без согласования не больше чем на `max_change_pct`
(по умолчанию 30%) за раз. «Полный доступ» снимает все согласования — включается
с подтверждением, его можно включить и прямо в чате.

API: `GET/POST /api/web/workspaces/{id}/chats`, `GET/PATCH/DELETE /api/web/ai/chats/{id}`,
`POST /api/web/ai/chats/{id}/messages`, `POST /api/web/ai/chats/{id}/decide-all`,
`POST /api/web/ai/actions/{id}/decide`.

### Расход ИИ: модели, токены, лимит

- Две модели: основная («умная») и быстрая. Задачи — `ai.TASKS`: чат — основная, разметка
  запросов и черновик брифа — быстрая. Быстрая не задана — всё делает основная.
- Цены — ₽ за 1 млн токенов входа и выхода, отдельно для каждой модели; у быстрой без своих
  цен — цены основной. Без цен расход считается только в токенах.
- Каждый вызов пишется в `ai_usage`: задача, пространство, модель, токены (из `usage`
  провайдера; если его нет — по длине текста, `estimated`), символы, число объектов в пачке
  и стоимость. «Настройки → Расход ИИ» — месяц по Москве: итог, полоса лимита, разрез по
  задачам, пространствам и моделям.
- Месячный лимит, ₽ (нужны цены): перед каждым вызовом сверяется с расходом с 1-го числа;
  исчерпан — ошибка `ai-budget`. Проверка подключения лимитом не ограничивается.
- Перед разметкой больше одной пачки — оценка без вызова ИИ: сколько закроют правила,
  сколько уйдёт в модель, токены, ₽, остаток лимита и сколько запросов в него влезет.
  Символов на токен и выходных токенов на запрос — по прошлым вызовам этой модели
  (до истории — 2,5 символа и 50 токенов). Во время разметки пачка, чья оценка не влезает
  в остаток, не отправляется: размеченное сохраняется, причина — в ответе.

API: `GET /api/web/ai/usage?month=ГГГГ-ММ`, `POST .../{id}/queries/classify/estimate`.

## Чистка запросов, бриф и откат

Экран «Поисковые запросы» пространства — одна очередь разбора. «Обновить из Директа» грузит
запросы за период, «Разметить с ИИ» размечает новые: сначала правила (запрос уже отсекается
минус-фразой в Директе, решение есть в памяти, слово из «точно не наше» брифа), остальное —
ИИ пачками по 40 (`AI_BATCH`): целевой или в минус, причина, минус-фраза и уровень (группа или
кампания; запрос без группы, например из автотаргетинга, минусуется в кампании). Перед
применением минус-фразы проверяются на пересечение со своими ключами. Пользователь
подтверждает выбранное пачкой: минус-фразы уходят в Директ (уже существующие не дублируются),
целевые можно сразу добавить ключами.

- Память решений: подтверждённые запросы больше не размечаются, ИИ получает их как примеры
  (до 40 каждого вида, `EXAMPLES_EACH`). Вкладка «Память» — список и «Забыть».
- Бриф (Настройки пространства → «Бриф клиента»): что продаём, география, «точно не наше»,
  заметки. «Черновик по сайту» читает сайт пространства (только публичные адреса, до 1,5 МБ)
  и заполняет поля через ИИ; применяется после «Сохранить бриф». Бриф видят разметка и чат.
- Откат: запись журнала хранит обратные шаги (`action_logs.undo`). «Вернуть как было»
  показывает шаги и предупреждает, если тот же объект меняли позже; откат выполняется задачей
  `undo_action`, пишется в журнал отдельной записью, исходная помечается «откачено».
  Повторно откатить нельзя, неудачный откат можно повторить.

API: `GET .../{id}/queries`, `POST .../{id}/queries/sync|classify|check|apply|forget`,
`GET .../{id}/queries/memory`, `POST .../{id}/brief/draft` (бриф сохраняется через `PATCH`
пространства, поле `brief`), `GET/POST /api/web/actions/{log_id}/undo`.

## Песочница Директа

«Аккаунты → Песочница Директа» — OAuth с режимом `sandbox`. Такое подключение (флаг `sandbox`)
ходит в `api-sandbox.direct.yandex.com`, кабинеты помечены «песочница». Удобно проверять
создание кампаний и ИИ-действия без денег. Песочница не связана с Метрикой: цели в стратегиях
недоступны. Перед первым входом откройте песочницу в веб-интерфейсе Директа
(«Инструменты → API → Песочница»), чтобы Яндекс создал тестовый кабинет.

## Общие списки минус-фраз

Страница «Минус-фразы» в кабинете: список стоп-слов создаётся с нуля или из шаблона, затем
отмечаются кампании любых клиентов. Нативные общие наборы Директа (`NegativeKeywordSharedSets`)
не используем: они вешаются только на группы (до 3 на группу, 30 на аккаунт) — вместо этого
список дописывается в `NegativeKeywords` кампании.

- Предпросмотр (`POST /api/web/negative-lists/{id}/preview`) считает по последнему синку,
  что добавится и уйдёт в каждой кампании; в Директ ничего не пишет.
- Применение (`POST /api/web/negative-lists/{id}/apply`) — задача `apply_negative_list`:
  перечитывает минус-фразы кампаний из Директа, сливает и пишет `campaigns.update` пачками по 10.
  Передаётся итоговый набор отмеченных кампаний: снятая галочка — отвязка списка.
- В `negative_list_campaigns.added_phrases` хранится, какие фразы добавил список. При отвязке
  или удалении фразы из списка уходят только они; фраза, нужная другому списку той же
  кампании, переходит к нему. Сравнение — без регистра и ё/е, как в Директе.
- Лимиты Директа: до 7 слов во фразе, слово до 35 символов, 20 000 символов на кампанию
  (без пробелов, дефисов и операторов). Медийные (CPM_*) и архивные кампании пропускаются.
- После правки списка связанные кампании помечаются «ждут обновления» до повторного применения.

## Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather), пропишите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`
2. В кабинете → «Получить ссылку» → Start в боте
3. Опционально webhook: `{PUBLIC_BASE_URL}/api/web/telegram/webhook`
   (задайте `TELEGRAM_WEBHOOK_SECRET` и тот же `secret_token` в `setWebhook`; иначе polling воркера)
4. Утренний дайджест включён по умолчанию в 9:00 МСК; час и отключение — в блоке Telegram
   на главной кабинета. Перед отправкой воркер догружает вчерашнюю статистику и балансы;
   если воркер лежал, дайджест догоняет в течение трёх часов. API: `GET/PUT /api/web/digest`,
   `GET /api/web/digest/preview`, `POST /api/web/digest/send`; сводка — `GET /api/web/overview`,
   `POST /api/web/overview/refresh`

## Тесты

```bat
cd backend
pip install -r requirements.txt
pytest -q
```

Без `TEST_DB_*` выполняются только юнит-тесты. Интеграционные (`tests/test_db_*.py`) **пересоздают
схему** — только в одноразовой БД, имя которой содержит `test`:
