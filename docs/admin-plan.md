# План переделки админки «Толк»

Дата: 2026-11-16. Сейчас админка — одна страница `/admin-panel` с девятью вкладками. План превращает её в рабочий инструмент владельца: боковое меню, дашборд с графиками, понятный список пользователей, реф-ссылки с группами, подробные расходы на ИИ, аналитика сайта и настройки, собранные в одном разделе.

**Как смотрели.**
- Код админки: `frontend/src/views/AdminView.vue`, 11 файлов в `frontend/src/views/admin/`, `frontend/src/api/admin.js`, `backend/app/api/admin.py`.
- Откуда берутся цифры: `users.py`, `billing.py`, `plans.py`, `payments.py`, `referrals.py`, `events.py`, `web_auth.py`, `api/site.py`, миграции `0001…0051`.
- Два референса владельца: дашборд и таблица реф-ссылок с группами.
- 28 вопросов владельцу. Ответы — в таблице «Решения по итогам вопросов».

**Что не проверено.** Это только план: код не менялся и не запускался. Скорость новых запросов на живой базе не измерялась — объём данных в проде неизвестен.

## Главный вывод

Проблем семь.

1. **Всё в одной куче.** Одна страница, девять вкладок в ряд. Рабочие списки (пользователи, платежи, оценки) стоят вперемешку с настройками (тарифы, ЮKassa, модели ИИ, мост, сайт).
2. **Список пользователей не помогает работать.** Показывает только первых 200, без поиска, сортировки и страниц. Нет суммы платежей, оплаченного срока, источника. На каждого пользователя идёт отдельный запрос в базу.
3. **Активность не записывается.** Сессия кабинета живёт долго, в журнал попадает только событие «Вход». Узнать, кто пользовался сервисом сегодня, сейчас нельзя.
4. **Нет дашборда.** Наверху — восемь плиток «работает / не подключено» и одна цифра оплат за месяц. Графиков нет, периода нет.
5. **Реф-ссылки — плоский список.** Групп нет. Переходы — один счётчик за всё время, по дням не разложить.
6. **Расходы на ИИ видны только за календарный месяц.** Нет графика по дням и разреза по задачам. Вызовы ИИ с лендинга (проверка сайта, генераторы) в расход не попадают вовсе: `billing.record` молча выходит, если нет пользователя. Ошибки моделей остаются только в логах сервера.
7. **Посещаемость сайта не считается.** На лендинге есть необязательный счётчик Метрики, своих данных о визитах нет — воронку «визит → регистрация → оплата» построить не из чего.

### Как устроено в коде

- `AdminView.vue` становится оболочкой: слева меню, справа страница. Страницы — вложенные маршруты vue-router, каждая грузится отдельно. Меню описано в `adminNav.js` по образцу `shellNav.js` кабинета.
- Старые адреса `/admin-panel?tab=…` перенаправляются на новые страницы.
- `backend/app/api/admin.py` (617 строк) делится на пакет `backend/app/api/admin/` по страницам: пользователи, дашборд, платежи, реф-ссылки, расходы ИИ, сайт, отчёты, система, настройки. Адреса существующих точек API не меняются.
- Стили админки выносятся из `shell.css` в свой файл `admin.css`.
- Вход по паролю остаётся как есть.

### Общие детали

- **Выбор периода** — один компонент на все страницы с цифрами: День, Неделя, Месяц, Квартал, Полгода, Год, Всё время и свой диапазон. Период хранится в адресе (`?p=30d` или `?from=…&to=…`) и запоминается в браузере: перешёл с дашборда на реф-ссылки — период тот же.
  - «День» — сегодня с 00:00 по Москве, сравнение со вчера до того же часа.
  - «Неделя», «Месяц», «Квартал», «Полгода», «Год» — последние 7, 30, 90, 180, 365 дней включая сегодня.
  - «Всё время» — без сравнения.
- **Шаг графика** — дни до квартала, недели для полугода и года, месяцы для «всё время». Шаг можно переключить вручную.
- **Карточка цифры** — значение, второстепенные цифры, изменение к прошлому периоду, подсказка «как считается».
- **Графики** — свои, на SVG, без сторонней библиотеки. `TrendChart.vue` уже умеет линию с пунктиром прошлого периода; добавляются несколько линий, столбики и столбики из частей. `Sparkline.vue` идёт в строки реф-ссылок.
- **Таблицы** — поиск, фильтры, сортировка и страницы считаются на сервере; состояние хранится в адресе.
- Все дни — по Москве (`app.clock`).

## 2. Учёт: что начинаем записывать

Этот этап идёт сразу за каркасом, раньше страниц: данные должны начать копиться.

### Заходы и действия пользователей

- Новое поле `users.last_seen_at` и таблица `user_activity_days`: пользователь, день, число заходов и действий, первое и последнее время.
- **Заход** — любой запрос вошедшего пользователя к кабинету. Пишется в `require_web_identity`, не чаще раза в 5 минут на пользователя.
- **Действие** — вопрос ИИ, выполненное предложение, созданный проект, правка кампании. Считается там же, где пишутся события (`events.record`) и журнал правок.
- Фоновые задачи (дайджесты, автопилот, ИИ по расписанию) активностью не считаются.
- **История.** До включения учёта дни восстанавливаются приблизительно — по событиям и вопросам ИИ. На графике старая часть отмечена границей «до этой даты — приблизительно». Заходы без действий за прошлое восстановить нельзя.

### Визиты сайта

- Таблица `site_visits`, одна строка на визит: обезличенный посетитель, день, страница входа, откуда пришёл (сайт-источник, UTM-метки, реф-ссылка), тип устройства, число страниц, пользователь — если потом зарегистрировался.
- Визит — как в Метрике: новый после 30 минут тишины.
- Посетитель — случайный идентификатор в браузере. Лендинг и кабинет живут на одном домене, идентификатор общий.
- Лендинг (`site/src/layouts/Base.astro`) и открытые страницы кабинета (вход, регистрация) шлют серверу короткое сообщение о просмотре на новую точку `POST /api/site/visit`.
- При регистрации идентификатор уходит вместе с реф-кодом — и по почте, и через Яндекс. В `users` сохраняется первый источник: метки, сайт-источник, страница входа. Отсюда колонка «Источник» и воронка.
- Боты отсекаются по User-Agent; запросы с одного адреса ограничены по частоте. IP не хранится.
- **Нужно ваше действие:** в текст политики cookies добавить строку про собственный идентификатор посетителя. Текст страницы `/cookies` правится отдельно.

### Клики реф-ссылок по дням

- Таблица `ref_link_clicks_daily`: ссылка, день, клики. Пишется в `referrals.visit`.
- Клик считается как сейчас: первый приход браузера по ссылке.
- Старый общий счётчик остаётся для «всё время». Мини-график начнёт заполняться со дня включения.

### ИИ

- `ai_usage.user_id` становится необязательным, добавляется поле «источник»: кабинет или лендинг. Проверка сайта и генераторы на лендинге начинают попадать в расход.
- В `ai_usage` добавляется ссылка на чат — для «самых дорогих чатов» — и длительность вызова.
- Новая таблица `ai_errors`: каждая неудачная попытка вызова — задача, модель, код и текст ошибки, была ли подмена, ответил ли кто-то в итоге. Пишется в цепочке повторов и подмен в `ai.py`. Хранится 90 дней.

## 3. Пользователи

### Список

Слева у каждой строки — **метка активности**: прямоугольник во всю высоту строки.

| Последний заход | Вид метки |
|---|---|
| сегодня | яркий зелёный |
| вчера | чуть бледнее |
| 2–3 дня назад | бледнее |
| 4–7 дней | ещё бледнее |
| 8–14 дней | едва заметный |
| больше 14 дней | серый |
| ни разу | пустой контур |

При наведении — «был сегодня в 14:20» или «был 5 дней назад».

| Колонка | Что показывает |
|---|---|
| Пользователь | Почта, имя, дата регистрации. Значки: вход через Яндекс, почта не подтверждена, заблокирован, есть непрочитанное обращение. |
| Источник | Реф-ссылка и цвет её группы, или UTM-источник, или «напрямую». Для личной ссылки — «от user@…». |
| Тариф | «Про · 3 мес. · 2 970 ₽» — тариф, срок и сумма последней покупки. Ниже мелко: «оплачено по 14.02.2027 · осталось 90 дн.». Пробный: «Пробный · до 20.11». Без оплаты: «Про · выдан вручную · до …». Истёк — красным «закончился 3 дня назад». |
| Оплачено всего | «5 мес. · 3 платежа» — сумма дней из успешных нетестовых оплат. Полностью возвращённые не считаются. |
| Платежи | Сумма оплат минус возвраты, ₽. |
| Лимит | Полоска «израсходовано 64%» за текущий период тарифа. |
| ИИ и маржа | Себестоимость ИИ за всё время и разница с платежами. Минус — красным. |
| Проекты | Число проектов, подключён ли Директ, число кампаний. |

Над таблицей:
- **Поиск** — почта, имя, номер, код реф-ссылки.
- **Фильтры** — тариф; подписка (платит, пробный, истекла, без тарифа); активность (сегодня, за 7 дней, пропал на 14+ дней, ни разу); источник (ссылка или группа); платил или нет; заблокирован; почта не подтверждена.
- **Сортировка** — регистрация, последний заход, сумма платежей, расход ИИ, дата окончания подписки.
- **Страницы** по 50 строк и итог: «Найдено 312 · платят 41 · заходили сегодня 27».

Сервер отдаёт страницу одним запросом вместо запроса на каждого пользователя.

### Панель пользователя

Открывается справа по клику на строку, адрес `?user=ID`. На неё ведут ссылки из платежей, обращений и расходов на ИИ.

- **Шапка** — почта, имя, источник, метка активности и лента за 30 дней (заходил / действовал). Кнопки: изменить подписку, подтвердить почту, заблокировать.
- **Обзор** — тариф, срок, индивидуальные условия, бонусные единицы, лимит периода; итоги: оплачено, срок, платежей, расход ИИ, маржа; проекты и Директ.
- **Платежи** — все платежи: дата, тариф, срок, сумма, статус, чек, возврат.
- **ИИ** — расход по дням за 30 дней и по задачам; список чатов с числом сообщений и стоимостью. Чат открывается для чтения — просмотр уже есть в «Оценках».
- **События** — журнал, как сейчас.
- **Обращения** — переписка и ответ, как сейчас.

Окно правки подписки остаётся прежним, открывается из панели.

## 4. Дашборд

Справа вверху — выбор периода. У каждой цифры за период — изменение к прошлому периоду.

### Карточки

| Карточка | Цифры | Как считается |
|---|---|---|
| Пользователи | Всего; новых за период | `users` по дате регистрации |
| С подпиской | Число и % от всех; строки по тарифам, «пробный», «без тарифа» | Действующая подписка на непробном тарифе |
| Истекают за 7 дней | Всего; на платном тарифе | Подписки с окончанием в ближайшие 7 дней. Клик открывает этих пользователей |
| Доход | За период; за всё время | Успешные нетестовые оплаты минус возвраты, по дате оплаты |
| Платежи за период | Количество; средний чек | |
| Платящие за период | Платящих; доход на платящего | |
| Конверсия в оплату | «N из M за W дней · ещё растёт»; за всё время | Зарегистрировались в периоде и оплатили за W дней. W = длина пробного тарифа + 7 |
| Платежей на платящего | За всё время | Платежей ÷ платящих |
| Удержание платящих | Удержание; возвратность; окончаний / досрочно / в день окончания / вернулись | См. ниже |
| Активные | Сегодня заходили и действовали; в среднем за день; за 7 и 30 дней | `user_activity_days` |
| Сайт | Визиты; посетители; регистрации; конверсия визита в регистрацию | `site_visits` |
| Вопросы ИИ | За период; на активного пользователя | События «Вопрос ИИ» |

**Удержание без автопродления.** Оплаты разовые, поэтому считаем по платежам. У каждого платежа есть последний оплаченный день (`payments.last_day`).
- Окончание — последний оплаченный день попал в период.
- Досрочно — следующая оплата пришла раньше этого дня.
- В день окончания — в этот же день.
- Вернулись — позже.
- Удержание = (досрочно + в день окончания) ÷ окончаний.
- Возвратность = (досрочно + в день окончания + вернулись) ÷ окончаний.

**Полоса «Состояние»** под карточками: ИИ, Вордстат, картинки, вход через Яндекс, ЮKassa, почта, мост, очередь задач — зелёная или жёлтая точка, клик ведёт в «Систему». Рядом: обращений без ответа, платежей без чека. Она заменяет нынешние восемь плиток.

### Графики

1. **Приток пользователей** — регистрации по дням, пунктиром прошлый период.
2. **Доход** — столбики по дням.
3. **Активные пользователи** — две линии: заходили и действовали.
4. **Вопросы к ИИ** — столбики по дням.
5. **Сайт** — визиты и посетители линиями, регистрации столбиками.

Все цифры и ряды дашборда сервер отдаёт одним ответом и держит минуту в памяти.

## 5. Реф-ссылки

Страница повторяет референс.

- **Группы.** Новая таблица `ref_link_groups` (название, цвет, порядок), у ссылки — поле группы. Ссылки без группы лежат в «Без группы».
- **Шапка.** «Создать группу», «Создать ссылку», «Развернуть все», «Свернуть все», переключатель «Личные скрыты · 617 личных», выбор периода.
- **Строка группы.** Цвет, название, число ссылок, итоги по всем колонкам. Сворачивается; состояние запоминается в браузере.

| Колонка | Что показывает |
|---|---|
| ☐ | Выбор строк: перенести в группу, выключить, удалить |
| ID, Код | Номер и код ссылки |
| Источник | Название ссылки |
| Ссылка | Адрес с кнопкой «скопировать» |
| Клики | За период |
| 7 дней | Мини-график кликов за последние 7 дней |
| Рег. | Регистрации |
| Оплаты | Сколько оплатили |
| Конверсия | Оплатили ÷ регистрации |
| Доход | Оплаты пришедших минус возвраты |
| Повтор. опл. | Вторые и следующие платежи |
| Каскад | Сколько людей привели пришедшие по ссылке через свои личные ссылки |
| Доп. доход | Оплаты этих приведённых |
| Создан | Дата |
| ⚙ | Переименовать, перенести в группу, выключить, удалить |

- **Период** действует на клики, регистрации и оплаты по дате события. По умолчанию — «всё время».
- **Личные ссылки** скрыты. Переключатель показывает их отдельной группой «Личные ссылки пользователей» с почтой владельца и теми же колонками.
- **Создание личной ссылки.** Сейчас она создаётся при открытии страницы «Тариф» (`PlanView.vue` сразу запрашивает `/api/web/referral`). Будет: условия бонуса видны без создания, сама ссылка создаётся, когда пользователь открывает блок «Ссылка для друзей». Уже созданные ссылки не трогаем.
- **Каскад** считается на один уровень: пришёл по ссылке → завёл личную ссылку → по ней пришли другие.
- Размер бонуса за приглашение уезжает в «Настройки».

## 6. Расходы на ИИ

Одна страница, шесть вкладок. Общий выбор периода и два фильтра: вид (модели, Вордстат, картинки) и источник (кабинет, лендинг).

### Обзор

- Карточки: себестоимость за период и изменение; в среднем за день; вызовов; цена одного вопроса в чате; доля входа из кэша и сколько кэш сэкономил; расход лендинга; списано единиц и наценка (единиц на рубль).
- График: расход по дням, столбики из частей — по классам моделей или по видам. Переключатель «рубли / вызовы / токены».

### Модели

- Таблица: модель, класс, вызовов, из них подменой, токены на входе с долей кэша, токены на выходе, рубли, цена вызова, доля в расходе.
- График по дням с разбивкой по моделям.

### Задачи

- Таблица по задачам (чат, разметка запросов, бриф, объявления, проверка сайта, генераторы лендинга, Вордстат, картинки): вызовов, токены, рубли, цена вызова, доля.
- По чату отдельно: цена вопроса, сколько вызовов модели уходит на один вопрос, десять самых дорогих чатов со ссылкой на просмотр.

### Люди и тарифы

- По тарифам: пользователей, выручка за период, расход ИИ, маржа в рублях и процентах, расход на одного. Отдельная строка — во что обходятся пробные.
- По пользователям: расход, выручка, маржа, единицы, доля лимита. Сортировка по любой колонке. Убыточные — расход больше платежей — выделены. Клик открывает панель пользователя.

### Надёжность

- График по дням: доля вызовов с подменой и доля ошибок.
- По моделям: вызовов, ошибок, доля ошибок, кого и кем подменяли.
- Причины отказов по частоте.
- Переплата из-за подмен — оценка: сколько стоили ответы запасных моделей против цены назначенных.
- Последние сбои из `ai_errors`.

### Журнал

- Лента отдельных вызовов: время, пользователь, задача, модель и подмена, токены (вход, из кэша, выход), единицы, рубли, ссылка на чат.
- Фильтры: пользователь, задача, модель, вид, источник, только подмены. Сортировка по стоимости — самые дорогие вызовы периода.

Карточка «Ответы „вниз“» со старой страницы «Расход» переезжает в «Качество ИИ».

## 8. Остальные страницы

**Платежи.** Список с поиском по пользователю и номеру. Фильтры: статус, период, тариф, без чека, тестовые. Итог по выборке: количество, сумма, средний чек, возвраты. Действия «сверить» и «чек отмечен» остаются. Клик по пользователю открывает его панель.

**Обращения.** Входящие поддержки: сначала без ответа; последнее сообщение, пользователь, тариф. Справа — переписка и поле ответа. Нужна новая точка API со списком переписок; сама переписка уже есть.

**Кому написать.** Готовые списки с количеством; каждый открывается таблицей: пользователь, причина, контакт, последний заход.
- упёрлись в лимит — кандидаты на тариф выше;
- подписка истекает за 7 дней;
- платная подписка кончилась и не продлена (до 30 дней назад);
- платили и не заходят больше 7 дней;
- зарегистрировались и за 3 дня не подключили Директ;
- подключили Директ, но не задали ни одного вопроса ИИ;
- пробный период кончается завтра.

Писать — вручную. Рассылок из админки нет.

**Сайт.**
- Цифры: визиты, посетители, регистрации, конверсия.
- График по дням.
- Таблицы: источники (реф-ссылка и группа, UTM, сайт-источник, напрямую), страницы входа с конверсией в регистрацию, устройства.
- Вкладка «Инструменты лендинга»: запуски проверки сайта и генераторов по дням, сколько перенесли проверку в кабинет.
- Вкладка «Лист ожидания».

**Воронка.** Шаги: визит → регистрация → почта подтверждена → подключён Яндекс → создан проект → вопрос ИИ → выполнено предложение → оплата.
- Для зарегистрировавшихся в периоде: сколько дошло до каждого шага, доля от предыдущего и от первого, обычное время между шагами.
- Срез по источнику: ссылка, группа, UTM. Сравнение с прошлым периодом.
- События для всех шагов после визита уже пишутся в `user_events`.

**Финансы.** Таблица по месяцам: выручка, возвраты, платежей, платящих, средний чек, расход на ИИ (с лендингом), маржа в рублях и процентах, новые и повторные оплаты. Выручка по тарифам и по срокам 1 / 3 / 12 месяцев. График «выручка и расход на ИИ».

**Качество ИИ.**
- Оценки, как сейчас, плюс доля «вниз» по дням, моделям и задачам, частые причины.
- Судьба предложений ИИ (`ai_actions`): предложено, одобрено, отклонено, выполнено, ошибка — по категориям и дням.
- Частые темы вопросов — позже и отдельным решением: разбор тем сам тратит ИИ.

**Проекты и Директ.** Сколько проектов, подключённых кабинетов и кампаний под управлением. Правки, применённые в Директе, по дням и видам. Кабинеты с ошибкой доступа. Проекты без кампаний.

**Система.**
- Состояние сервисов с кнопкой «Проверить».
- Очередь задач: ждут, выполняются, упали — по видам; самая старая ждущая.
- Расписания: когда запускались в последний раз.
- Последние ошибки синхронизаций и ИИ.
- Размер базы и версия сервиса.

## 12. Риски и открытые места

1. **История активности неполная.** Заходы без действий до включения учёта восстановить нельзя. Метки и график станут точными через две недели после этапа 2.
2. **Клики по дням — только с этапа 2.** Мини-графики в первые дни пустые.
3. **Политика cookies.** Свой идентификатор посетителя надо упомянуть в тексте. Это ваше решение и ваш текст.
4. **Расход лендинга.** Поле пользователя в `ai_usage` перестаёт быть обязательным. Надо пройти все запросы, которые на это опираются, — в первую очередь расчёт лимитов.
5. **Переплата из-за подмен — оценка**, а не точная цифра: цена назначенной модели прикидывается по её классу.
6. **Скорость.** Расход ИИ за всё время по каждому пользователю считается по исходной таблице. На большом объёме понадобится дневная сводка.
7. **Метка и восемь колонок в списке пользователей** — плотно даже на широком экране. Ячейки в две строки; если тесно — редкие колонки прячутся переключателем.
8. **Конверсия зависит от длины пробного тарифа.** Поменяете длину — окно пересчитается и для прошлых периодов.
